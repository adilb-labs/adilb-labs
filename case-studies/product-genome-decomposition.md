# Product Genome & Product Decomposition — Case Study

## Problem

Many AI-assisted software projects start coding before the product itself is sufficiently defined.

The result is often:

- scope drift;
- conflicting requirements;
- duplicated features;
- architecture built around assumptions instead of domain truth;
- unclear MVP boundaries;
- expensive rewrites.

## Method

The Product Genome approach separates product understanding from implementation.

A product is decomposed into a bounded set of concerns such as:

- problem and value;
- users and roles;
- workflows;
- domain entities;
- functional capabilities;
- risks and failure modes;
- platform and integration constraints;
- sources of truth;
- V1 vs deferred scope;
- acceptance criteria.

The output is intended to become the minimum complete product truth needed before expensive implementation continues.

## Typical deliverable

A Product Genome Intelligence Report / AI Product Decomposition Audit can include:

- scientific/functional product definition;
- user and role analysis;
- domain structure;
- capability map;
- dependency map;
- risk map;
- MVP / V1 boundary;
- architecture direction;
- acceptance criteria;
- build / repair / defer recommendation.

## Commercial use

This is especially useful for:

- founders with an AI-built prototype;
- teams whose roadmap has become inconsistent;
- products that grew from prompts instead of requirements;
- clients deciding whether to continue, repair, or rewrite;
- projects that need a clean handoff to a new developer or AI model.

## Claim ceiling

This is offered as a **bounded product-intelligence and architecture service**.

It does not claim that every product analyzed by the method has already been built, launched, or commercially validated.
